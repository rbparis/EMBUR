# EMBUR texting setup

EMBUR uses Twilio Programmable Messaging. Delivery is disabled unless the
server configuration explicitly selects `test` or `live` mode.

## Required Vercel environment variables

```text
TWILIO_ACCOUNT_SID=AC...
TWILIO_AUTH_TOKEN=...
TWILIO_MESSAGING_SERVICE_SID=MG...
TWILIO_WEBHOOK_BASE_URL=https://getembur.com
TWILIO_COMPLIANCE_STATUS=unregistered
SMS_DELIVERY_MODE=disabled
SMS_TEST_TO_NUMBER=+1...
```

`TWILIO_PHONE_NUMBER=+1...` may be used instead of a Messaging Service SID,
but a Messaging Service is preferred because it supports sender pools,
Advanced Opt-Out, and campaign registration.

Never prefix these variables with `NEXT_PUBLIC_`. They are server-only secrets.

## Safe activation order

1. Create or upgrade the Twilio account.
2. Create a Messaging Service and purchase a text-capable number.
3. Complete the correct U.S. A2P 10DLC registration for the business and use
   case, or complete Toll-Free verification if using a toll-free sender.
4. Enable Advanced Opt-Out for the Messaging Service.
5. In Twilio, set the inbound message webhook to the URL shown in
   **EMBUR → Settings → Customer texting**. Use HTTP `POST`.
6. Add the server variables to Vercel with:

   ```text
   TWILIO_COMPLIANCE_STATUS=pending
   SMS_DELIVERY_MODE=test
   ```

7. Set `SMS_TEST_TO_NUMBER` to a phone controlled by the EMBUR owner and run
   a test. Test mode always redirects delivery to that safe number.
8. After the campaign or sender verification is approved, change:

   ```text
   TWILIO_COMPLIANCE_STATUS=approved
   SMS_DELIVERY_MODE=live
   ```

9. Redeploy and verify one consented customer conversation.

## Safety behavior

- A signed-in owner must click **Approve & send text**.
- Texts are blocked without documented consent from an intake submission or
  an inbound SMS conversation.
- A customer's latest `STOP` event blocks future delivery until a later
  `START` event is received.
- Twilio webhook signatures are validated before EMBUR accepts inbound
  messages or delivery events.
- Delivery status is written back to the conversation timeline.
- Test mode never sends to the customer's number.

## Twilio webhook routes

- Inbound messages:
  `https://getembur.com/api/messaging/twilio/inbound/{businessId}`
- Delivery callbacks:
  `https://getembur.com/api/messaging/twilio/status`

The delivery callback query string is generated by EMBUR for each conversation.
